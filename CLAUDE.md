## Секреты — строгие правила

- Ключи лежат вне папки проекта: `~/.vast_api_key` — API-ключ Vast. Позже переедут в Keychain macOS.
- **Никогда не читай, не выводи и не копируй файлы с ключами и токенами.** Код может читать ключ, ты — нет. Не печатай ответы API целиком, если в них могут быть секреты: выводи только нужные поля.
- Ключи никогда не попадают в код, в git и в логи. В `.gitignore`: `.venv/`, `__pycache__/`, `.env`, `*.key`.
- API-ключ Vast по умолчанию полный: им можно арендовать машины и тратить деньги. **Любое действие, которое стоит денег (аренда), — только после моего явного подтверждения в этот момент.** Удаление инстанса — тоже.

## Что строим

Консольную утилиту на Python (готова, команды ниже), а поверх неё — настольное приложение на **pywebview** (Python + интерфейс веб-страницей в окне; решение 2026-09-23 вместо Tauri, чтобы весь проект был на одном языке). Команды утилиты:

- `balance` — баланс Vast (`balance.py`, готово).
- `offers` — таблица подходящих машин: GPU, цена в час, страна, надёжность, трафик (`offers.py`, готово; поиск — общий `market.py`).
- `play` (`play.py`, готово) — без ID подбирает машину сам (`market.search`: все страны, RTX/GTX, KVM, надёжность от 0.97, сортировка по полной цене часа; показывает пятёрку со странами — задержка зависит от расстояния, Enter — №1); с ID — конкретную. Хосты, которые не смогли запустить машину, — в `~/Library/Application Support/vastgame/bad_hosts.json` (по `machine_id`). **Решено 2026-09-24: не прятать, а помечать** («может не запуститься», `o["_failed"]`; сбой бывает временным); пометка снимается, когда машина на хосте дошла до `running` (`market.clear_bad` в `core.wait_ready`). Арендовать выбранную машину по шаблону, дождаться готовности, показать адрес для Moonlight. Выключатель «загружать игры из облака» — передаётся при аренде как `SYNC_STEAM_GAMES=0/1` (скрипт читает его только при старте инстанса, поэтому действует со следующей аренды).
- `stop` — выгрузить всё на инстансе, дождаться подтверждения и только потом удалить инстанс (`stop.py`, готово).
- `migrate` (`migrate.py`) — перенос архивов из старой папки в папку приложения (разовый, при переходе на свой OAuth-клиент).
- `games` (`games.py`, готово) — игры и сохранения в облаке с размерами — прямо с Drive через rclone на Mac, машина не нужна; названия сохранений (`pfx--<appid>`) — из публичного API магазина Steam. `games rm <название>` — в корзину Drive (30 дней): при работающей машине через `wolf forget` по SSH (иначе wolf выгрузит заново), без машины — `rclone deletefile --drive-use-trash=true`. Служебные архивы не удаляются.
- `info` (`info.py`) — адреса работающей машины: Moonlight (имя MagicDNS), кабинет Sunshine `https://<узел>:47990`, статус `:8099`; те же адреса печатает `play` в конце.
- **Ядро — `core.py`** (шаг 1 приложения, готов): `play`/`stop` как функции без печати и `input()`; общение через объект `ui` (`say`, `stage`, `archive`, `confirm`, `tailscale`). Этапы `stage`: `vast` → `tailscale` → `restore` → `ready`; `shutdown` → `verify` → `deleted` — по ним будет меняться значок. Терминал — `cliui.ConsoleUI`; `play.py`/`stop.py` — тонкие обёртки. Ошибки — `vastapi.VastgameError` (подвид `SystemExit`: в терминале = sys.exit; окно ловит явно, `except Exception` её НЕ ловит). Вывод `wolf shutdown` читается параллельно (иначе переполнение канала и взаимная блокировка).
- **Автотесты:** `tests/test_core.py` — ядро с поддельными Vast/Tailscale/ssh/`/json`, без денег и сети: нормальный запуск; ошибка хоста → чёрный список и удаление после «да»; «нет» — не удалять; нормальная остановка; выгрузка не подтвердилась / ошибка shutdown / «нет» — не удалять; старая ошибка не мешает; dry-run ничего не меняет. Запуск: `.venv/bin/python -m unittest discover -s tests -v`. Проверено порчей кода: ловят. Прогонять после любых правок `core.py`.
- **Окно (`gui.py` + `ui/`):** pywebview 6.2 (на Mac — WebKit). `gui.Api` — функции для страницы (`window.pywebview.api.*`), каждый вызов в своём потоке; `VastgameError` ловить явно. Состояние — `core.status()`: none / starting (+stage vast|tailscale|restore) / ready / syncing / error; «выключается» снаружи не видно — показывает окно, которое запустило stop. Демо-режим страницы для проверки вида без аренды: `ui/index.html?demo=none|starting|ready|syncing|error|low` через локальный сервер (`.claude/launch.json` → `ui-demo`, порт 8765; файл не в git). В CSS `[hidden]{display:none !important}` — иначе `display:flex` перебивает `hidden`.
- **Языки окна: ru, en, es** (решение 2026-09-23; терминал остаётся на русском). Все тексты окна, включая сообщения ядра, — `ui/i18n.js` (строгий JSON внутри, ключи вида `status.title.ready`, подстановки `{имя}`). Python передаёт ключ и данные, переводит страница. Ядро отдаёт не фразы, а вид и данные (`status()["kind"]`, `done`, `busy`...) — фразу собирает окно. Язык: выбор человека в `settings.json` (`settings.py`, папка настроек), иначе язык системы. Автотест `tests/test_i18n.py`: одинаковые ключи и подстановки во всех языках. Испанский перевод стоит показать носителю.
- **«Играть» в окне:** экраны выбор машины (10 лучших, `Api.offers`) → подтверждение со свежей ценой (`Api.check_offer`, окно `ask`) → `Api.play` запускает **фоновый процесс** (`jobs.py`, см. ниже) → страница раз в секунду забирает `Api.session_progress(since)`: этап, события (ключ+данные, переводит страница), архивы. Перед арендой ядро ещё раз проверяет «машин нет» (`core.require_no_machine`); вторая операция при идущей — `busy`. Закрытие окна: play/stop идут дальше в фоне; спрашивает (`askClose()` на странице) только при короткой операции в самом окне — убрать игру, установка (системный диалог из обработчика закрытия повесил бы окно — он в главном потоке). `tests/test_gui.py` — Api с поддельным ядром.
- **«Закончить» в окне:** вопрос «Закончить игру?» → `Api.stop` (фоновый процесс, `core.stop`) → этапы shutdown → verify → deleted; ссылка подтверждения Tailscale SSH — блок с кнопкой (события `tailscale` с `url`), прячется после `core.ssh_ok`. **Удаление без вопроса (решение 2026-09-24)** — сразу после подтверждённой выгрузки; не подтвердилась / `/json` не ответил / shutdown упал — не удаляем. Машину, которая не запустилась (`_failed_start`), тоже удаляем без вопроса — на ней ничего не было. Кнопка активна при ready/syncing/error. **«Удалить без выгрузки»:** два вопроса на странице → `Api.emergency_delete(id)` → `core.emergency_delete(expected_id)` удаляет только машину с тем номером, что видел человек; при идущей операции — `busy`.
- **«Запустить Moonlight»** (главный экран при готовой машине и экран «Готово»): `moonlight.py` — `Moonlight list <узел>` даёт приложения Sunshine (нужна связка по PIN), `Moonlight stream <узел> "<приложение>"` открывает трансляцию. Выбор приложения запоминается (`settings: moonlight_app`), по умолчанию «Desktop». `wolf-setup.sh` приложения Sunshine не настраивает — стандартные Desktop и Steam Big Picture (или свои из кабинета Sunshine, едут в identity). Проверено на живой машине 2026-09-24: кнопка открывает трансляцию.
- **Игры в облаке в окне:** кнопка на главном экране → `Api.games()` (`cloudgames.listing`, прямо с Drive) → таблица (тип, название, размер, дата, «Убрать»); сохранения — с громким предупреждением. Удаление — фоновый Job «games» (`cloudgames.remove`): без машины — rclone в корзину, с машиной — `wolf forget` по SSH (ссылка Tailscale — блок в экране игр), машина без Tailscale — отказ. Логика в `cloudgames.py`, `games.py` — тонкий терминал. Тесты `tests/test_cloudgames.py`.

- **Фоновые операции (`jobs.py`, решение 2026-09-24):** «Играть» и «Закончить» — отдельный процесс `python jobs.py play|stop '<json>'` (`start_new_session`), переживает закрытие окна (проверено: родитель вышел — процесс довёл до конца). Ход — `job.json` в папке настроек (атомарная запись), жив ли — блокировка `job.lock` (`fcntl.flock`, снимается системой при смерти процесса), вывод — `job.log`. Вопросов нет (`FileJob.confirm` → «нет»). В конце — уведомление (`notify.py`, osascript; тексты `notify.*` из `ui/i18n.js` на языке окна — страница передаёт `lang`). Окно при открытии: `state()["task"]` — идёт (`active`) или закончилось без окна (`unseen`) → экран хода; «На главный экран» → `session_seen`. Процесс умер без `done` → ошибка `progress.lost`. ## Как устроена система (уже работает, не ломать)

- Как система устроена целиком (для пользователя) — `README-wolf.md`. Читай его, прежде чем выводить устройство из кода.
- На инстансе работает `wolf-setup.sh` — он лежит в этой папке (v3.8). Шаблон `vastgame` качает скрипт из репозитория проекта на GitHub по ссылке на коммит (`SCRIPT_URL`, `SCRIPT_VERSION` в `setup.py`). Новая версия: опубликовать (`gh api -X PUT repos/WetFoxx/Vast.ai-Cloud-Gaming-/contents/wolf-setup.sh`), сверить побайтно по ссылке на коммит, поменять `SCRIPT_URL`, вызвать `setup.refresh_template()`. В v3.8 `SYNC_STEAM_GAMES` по умолчанию `1`, но шаблон всегда задаёт его явно. Это «агент»: восстанавливает из Google Drive сессию Steam, сохранения и сетевую личность, выгружает изменения обратно, управляет разрешением экрана. **Читай его, когда нужно понять, что происходит на инстансе.**
- Vast: образ `docker.io/vastai/kvm:ubuntu_desktop_22.04` (нужен именно KVM, не контейнер). Шаблон для утилиты — приватный `vastgame`: его создаёт/обновляет мастер (`vastgame setup`, шаг «Шаблон»; содержимое — константы в `setup.py`: образ, порты с `41641/udp`, служебные переменные портала Vast, загрузчик, фильтры, настройки RES/SYNC_STEAM_GAMES/STEAM_LANG и `recommended_disk_space`). Ключей в нём нет. `vastapi.my_template()` ищет его по имени (hash_id меняется при каждом сохранении). Создание — `POST template/`, изменение — `PUT template/` с `hash_id` в теле, удаление — `DELETE template/` `{"hash_id"}` (как в CLI). `extra_filters` — объектом. Старые шаблоны Алексея: `WETFOX CLOUD GAME` (порт 741641, загрузчик на ревизии 787acea = v3.7) и `WETFOX CLOUD GAME TEST` (ключи внутри, загрузчик без ревизии). Прежний `WETFOX CLOUD GAME`: `hash_id=49faada2e6e7fe3e15bef0ea1999420a`. При сохранении шаблона на сайте меняется `hash_id` — искать через `GET template/` с `select_filters={"name": {"eq": ...}}`. ## Vast API

Проверено по документации (docs.vast.ai/api-reference) и на живом API. Общий код запросов — `vastapi.py`.

- База: `https://console.vast.ai/api/v0/`, авторизация заголовком `Authorization: Bearer <ключ>`.
- `GET users/current/` — данные аккаунта. Деньги на счету — поле `credit` (сверено с консолью; `balance` — другое, обычно 0).
- ~~`GET instances/`~~ — отключён (HTTP 410). Список инстансов — `GET https://console.vast.ai/api/v1/instances/` с параметрами `select_filters`, `order_by`, `limit` (JSON в query), по страницам через `next_token` → `after_token` (`vastapi.list_instances`).
- `GET instances/<id>/?owner=me` — один инстанс в `{"instances": {...}}` (`null`, если нет). Поле `actual_status`: ждём `running`; из `exited`/`offline`/`unknown` до `running` уже не дойдёт.
- `DELETE instances/<id>/` (тело `{}`) — удаление, ответ `{"success": ...}`.
- Ошибки: объяснение в поле `msg`.
- `POST bundles/` — поиск предложений; фильтры в JSON вида `{"gpu_name": {"eq": "RTX 4090"}, "rentable": {"eq": true}, "num_gpus": {"eq": 1}, "order": [["dph_total", "asc"]], "type": "ondemand", "limit": 20}`. Проверено на живом API:
  - `gpu_name` — с пробелом: `"RTX 4090"`. Вариант из документации `RTX_4090` находит 0 машин.
  - `type`: работают и `"ondemand"`, и `"on-demand"`.
  - KVM: `"vms_enabled": {"eq": true}` — из ~700 машин с 1 GPU подходят ~70.
  - `dph_total` зависит от `"allocated_storage": <ГБ>` в запросе: без него цена считается под диск 8 ГБ и занижена.
  - Трафик: `inet_up_cost` (исходящий — стрим) и `inet_down_cost` (входящий — скачивание из Drive), в $ за ГБ. У большинства хостов ~0.003–0.004 $/ГБ, у единиц — практически 0.
  - Прочие поля: `reliability` (0–1), `disk_space` (ГБ свободно), `geolocation` (`"Quebec, CA"`, бывает `", CN"`), `storage_cost` ($/ГБ/месяц).
- `PUT asks/<offer_id>/` — аренда; в ответе `new_contract` — это id нового инстанса. Тело (как в официальном CLI): `{"client_id": "me", "template_hash_id": "...", "disk": 100, "label": "vastgame", "env": {"SYNC_STEAM_GAMES": "1"}}` — `env` словарём, сливается с env шаблона. Переменные из Environment Variables аккаунта попадают в любой инстанс; в VM env пишется в `/etc/environment`.
- Поиск машины по ID: `"ask_contract_id": {"eq": ID}`. Фильтр `"id"` молча находит 0.
- Переменные аккаунта: `GET secrets/` → `{"secrets": {имя: "********"}}` — значения замаскированы, сверять можно только имена. `POST secrets/` `{"key", "value"}` — создать, `PUT` — заменить, `DELETE` `{"key"}` — удалить (как в CLI). Запись — `setup.py vast`.
- Бывают ключи с ограниченными правами (например, без доступа к биллингу) — перейти на такой, когда определимся с нужными правами.
