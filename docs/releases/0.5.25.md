# VastGame 0.5.25 beta

## Steam Isolation Hotfix

- Исправлен запуск Steam на части Docker-серверов Vast.ai, где контейнер запрещает user namespaces или возвращает `ENOSYS` для отдельных системных вызовов.
- Steam Linux Runtime по-прежнему запускается штатно: VastGame сначала пробует обычный `bubblewrap`, а на ограниченных хостах автоматически передаёт Steam и Proton закреплённый `proot-next` через `BWRAP` и `PRESSURE_VESSEL_BWRAP`.
- Устранена проблема подготовки Proton-префиксов, когда старый seccomp-профиль контейнера запрещал `fchmodat2`: теперь используется безопасный запасной вызов только при `ENOSYS`.
- Не требуется вручную отключать проверку Steam или изменять его внутренние файлы. Старый механизм остаётся доступен только как явный аварийный режим.
- Прямые запуски через `vg-run`, запуск игр через `vg-launch` и офлайн-запуск программ для модов наследуют то же окружение изоляции, что и обычный запуск Steam.

## Технические ограничения этого хотфикса

- Живое испытание выполнено на Docker-хосте Vast.ai с заблокированными user namespaces; PEAK запускалась обычным способом через Steam Linux Runtime и Proton.
- Подтверждены Steam, запуск PEAK, изображение Moonlight, штатная аудиоцепочка и получение реальных событий виртуального контроллера Sunshine/vgpad.
- Не заявляется исправление всех игр, всех контроллеров или всех хостов Vast.ai.
- Полноценные live-проверки KVM, MO2/Vortex, отдельной реакции каждой кнопки контроллера в игре и Docker-хостов со штатно работающим bubblewrap в этот хотфикс не входили.
- Прямой WireGuard, облачная диагностика и другие незавершённые функции не включены.
